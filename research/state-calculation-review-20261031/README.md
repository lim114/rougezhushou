# 本局信息到计算显示的回顾

基线：`92bd5b780f50da41e5bdb2e5f6d93098a94c64f2`。本轮为实现维护，功能节数仍440。完整程序回顾和视频全部效果仍未完成。

## 已确认的问题与修正

同一份本局更新依次同步难度、藏品、干员培养与技能；每个回调可能再次计算，读到的是一批尚未全部更新的控件。原代码在`update_skill_options()`之后还有一次相同的计算。隔离实际运行中，本局更新调用计算3次，同帧本局和账号更新调用5次，手动换干员调用2次。

现在相关更新范围结束后，**同步计算一次最终输入**，不等待下一帧或定时器；独立修改等级、技能和其它条件仍立即计算。嵌套范围合并请求，失败时释放范围并保留原有异常，不发布尚未完成更新的输入。此范围不缓存结果、不锁定输入、不回滚状态、不改变保存方式或计算公式。

藏品列表同步原来在每个勾选框中重读持有清单，实际一次同步读273次（含最终计算内部使用）。现该循环只取一次集合，算上计算内部使用为2次。此前由`update_skill_options()`保证执行的重复计算及其重复守卫删除。持有资格、损坏文件、本局恢复、未确认强化与防重复发送保护均保留。

同时更正`training_view.py`仍自称“尚未导入的提案”的旧模块说明；其运行语句AST与基线完全相同，不把改说明当作机制改动。

## 替代方案与依据

- 复用[Python 3.12 contextlib](https://docs.python.org/3.12/library/contextlib.html#contextlib.contextmanager)管理嵌套更新范围，退出和异常路径集中处理；不增加依赖或线程。
- 不用`QTimer`延迟计算，避免读取刚修改的界面时还拿到旧结果；不用全局结果缓存，避免本局计数和来源变化未进入缓存键。
- [Qt QSignalBlocker](https://doc.qt.io/qtforpython-6.11/PySide6/QtCore/QSignalBlocker.html)可恢复信号阻断状态，但屏蔽整批控件信号也会跳过必须的技能、培养和目标联动。本轮保留这些联动，仅合并计算请求。
- REA既有工具条和桥接证据继续保留。本轮完整Python源码使用源码追踪和受控实际重放；未把新生成字节码或语法扫描当成额外正确性证明。

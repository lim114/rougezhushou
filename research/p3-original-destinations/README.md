# Original destination reference navigation

This source-backed feature turns the literal `nextSceneId` fields into a readable, modeless destination browser, without treating them as an origin relation or executed transition. The complete pinned source has 396 choices and 338 scenes; 306 choices declare a target and 90 do not. All target IDs exist in the pinned scene table. The UI covers event-option original-ID candidates and the 37 previously bare unclassified choice references with explicit targets.

The primary table bytes were independently SHA-checked against the pinned source (`a550f5e048bb94e7cdefc6eb97a4091f0c4c7add`, `f5867e55d09472253083486174aa47bd94dd48b07684b74b60a5b29ca00eda86`). `selected-original.json` preserves all complete selected choice/scene rows. Every extracted field was compared with the shipped original-node data. Original scene objects do not include a choice relation field; choice objects expose their destination only. No relation was invented from ID suffixes, titles, prose, or option type.

An exact destination ID may independently match existing `game_scene_ids` in fixed community revision 427904. These existing catalog bindings are immutable source references, not recovered server origin scripts. Every matching destination scene stays separate. Conditions and stage links come from that exact scene's existing independent planners, never from NEXT itself. Eleven original choice targets contain independently documented battle links; previews retain all fixed stage aliases and unknown eligibility. Declared mismatches remain readable reference material. Explicit targets without catalog bindings show original prose and unknown options/battles.

The destination comparison clears origin node type / natural-entry mode, uses declared content-reference context, and does not assert state continuity after a transition. No inventory, run memory, map-node binding, probability, game action, or chat message is created. The 25 unclassified original scenes and 57 unproven original choice-origin pairs remain separate gaps. A visible destination window keeps its choice, exact preview candidate and reading state when its same source selection refreshes. If the reader navigates elsewhere, the modeless window remains an independent comparison snapshot; reopening the source updates its declared context. Controls disappear for entries without applicable pointers.

The generated artifact binds exact current source-file byte hashes and per-record canonical fingerprints. Reproduction is byte-equal. Twelve new API/real offscreen Qt tests plus 32 relevant unchanged tests passed. Initial mistaken fixtures are preserved in `first-tests.txt`; they were replaced by actual source fixtures rather than changing mechanisms. Offscreen Qt is not a claim of native visible acceptance. Root owns actual Windows review and serial integration.

Sources: the pinned GitHub original table URL and fixed PRTS catalog URL are included in the generated artifact and primary receipt. No current revision or whole-server completeness is claimed.

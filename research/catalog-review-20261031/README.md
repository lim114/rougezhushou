## 发现与实际替换

| 发现 | 处理与适用边界 |
| --- | --- |
| 收藏品刷新先生成全部条目，再重复读取和生成一次用于筛选。每次还经过包含旧版效果、变化标签和其它分类的通用目录。 | 每次核对固定来源后，只构建一次当前物品字段，复用同一结果生成分类与筛选。保留准确ID、原顺序、当前图鉴范围和持有标志；资料失效仍清旧内容。没有跨刷新缓存未核对的资料。 |
| 同名统计逐名称扫描整个目录；干员分组也重复全表计数。 | 复用Python标准库`Counter`一次计数。资料编号与原排序保持，未把同名变体合并。 |

| 收藏品目录65条没有对应的独立文件，其中39条已有共用原图的核验记录。 | 列表和藏品卡复用既有13组明确共图关系。各变体仍用自己的ID、中文名、效果、来源池和入口；图片不反推档位、持有或计算结果。不按文件名后缀猜其它共图关系。其余26条仍缺参考图片。 |

不是所有代码都适合删除。固定资料来源核对、损坏记录保护、发送未确认时不重发和未保存笔记处理仍有实际用途。此次删除的是无用的重复构建、无关旧效果复制及预先缩放步骤，没有因为罕见就移除本局记录保护。

## 实测与一致性

最终前后各3个独立Windows Qt进程交错运行，均用相同公开资料及临时空局。主窗口构建不含Python进程和模块导入；收藏品刷新先一致预热，每次7个样本。完整原始值、实际子进程退出和源码摘要见[验收目录](../../verification/maintenance/catalog-review-20261031/final-benchmark/)。

- 构建中位数约1.93秒→1.42秒；收藏品刷新中位数约147毫秒→37毫秒。三轮样本很少，只代表该同机场景，不是全部操作、游戏读取或识别加速。
- 每个进程比较432组收藏品筛选、10类资料的全部/变化两种模式、8个职业分组；新旧完整文字与结构结果摘要完全一致。此对照不证明资料机制或当前服务器本来就正确。
- 初轮95项相关检查通过；接通共图显示后，最终43项相关检查及414/396原生范围分别20/21项通过，重叠不合计为独立总数。实际窗口确认筛选、缩放、键盘阅读、头像、技能及原阅读状态保持。两轮原件分开保留，未覆盖旧回执。
- 已实际查看原片172秒收藏品页、初轮两张与最终两张原生窗口图。仍存在资源条、比例、说明密度和其它窗口的外观差异，不称整套视频一致。
- 原项目测试小窗正常更新并保持打开；启动区间六份私人路径仅核对摘要，内容和摘要不发布。没有操作游戏、发送聊天或访问真实服务商。

新测试初期暴露两项验收假设错误并已更正：物理像素不能直接与逻辑尺寸比较；原目录中明确无图片的条目不能当作已有图片。前者按实际DPI计算，后者保留缺图，不借其它敌人头像补齐。未将这些测试假设错误宣称为新增程序缺陷。

## 复用依据与未采用方案

- [Python 3.12 Counter](https://docs.python.org/3.12/library/collections.html#collections.Counter)：直接复用标准库计数，没有引入依赖。
- [Qt QIcon文件加载](https://doc.qt.io/qtforpython-6/PySide6/QtGui/QIcon.html#PySide6.QtGui.QIcon.addFile)：按需加载并按显示尺寸提供图片。文档明确非空文件名不代表图片有效，因此用实际`pixmap()`解码检查，不能拿`isNull()`代替资源完整性。
- 本项目既有`relic-reference-equivalence.json`、`relic_recognition.artwork_families`及原第32节来源核验：只复用明确列出的共图关系，不改识别算法或推断当前档位。原核验来源是PRTS具名表格及固定游戏难度映射，范围不是当前服务器实测。
- [REA技能](C:/Users/李娜/.agents/skills/reverse-engineer-anything/SKILL.md)将完整源码仓库分析与二进制/运行证据分开。已有工具条字节码和桥接静态证据保留；本轮Python使用源码阅读、实际性能采样和原生窗口验证，未人为编译一堆`.pyc`冒充全程序逆向完成。
- 不采用仅靠修改时间的全局资料缓存，也不为此次优化整套重写或加入新的窗口框架。它们会增加失效处理与迁移验证，尚无同等证据证明总成本更低。

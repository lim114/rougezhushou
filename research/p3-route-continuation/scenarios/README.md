# 有限声明情景的路线矩阵

`scenario_route_matrix(graph, routes, scenarios)` 将同一声明图/方案与最多10个独立明确状态相结合，保留每个状态的原输入、移动参考、来源数量账本和居民阶段。每条路线最多10步，步行逐条相邻连线声明。它不生成隐藏状态、不赋概率、不宣称实际最优。

各状态必须显式声明 `action_points`、`inventory` 与 `passive_items`；`null` 是快照未知，`[]` 是明确为空，不互相替换。已有计划缺少实例时只标该路线的精确阻断/未知原因及步骤，不丢掉整个矩阵。缺末步实例前的已知前缀可保留条件来源小计和居民参考，完整路线总量仍未知。未知快照也会向嵌套来源账本资格传播，不能露出“完整零资源”结论。

每条路线汇总移动、数量、居民偏好以及复合条件的覆盖状态。数量包络只在全部已列情景中所列数量条件闭合时给出，否则为未知。敏感性见证保存情景ID对和变化字段；即使移动状态都闭合，行动力变化导致FINAL条件希望数量改变，也会留下见证。

跨情景的保守分项关系只在同终点、同独立转移、所列数量闭合且偏好匹配时求值。希望/护盾授予、基础经验、源石锭范围与净行动力保持独立轴；随机品价值不排序。规则返回不符合，不意味着实际更差。居民候选交集偏好不等于真实安全，未知回退与快照保留。

`RouteScenarioMatrixPanel` 提供七种复合公开状态、完整/未知阶段预设、选择情景编辑AP及实例余次数、中文扫描矩阵、数量范围、见证和完整来源详情。明确缺实例、未知快照及仅前缀参考分别显示。继承已封存编辑/地图绑定组件，保留刷新、选择、滚动和旧输入结果保护。

来源见 [source-receipt.json](source-receipt.json)，沿用前三组固定原件、来源资格和条件账本，没有新增游戏脚本或数字。验收见 [verification.json](verification.json)：11项行为和4项Linux Qt检查通过，实际1320×1020组件窗口已检查中文矩阵。原生Windows、游戏、当前服务器与聊天联调未由本回执验证。

该组最初只存于 `work/route-scenarios-draft/`，不进入第245节生产全量快照。由主代理串行复制、集成、更新状态和普通提交推送。

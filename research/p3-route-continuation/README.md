# 有限声明图的必经、避开与顺序路线规划

`rouge.route_constraints.constrained_routes` 在搜索状态中维护尚缺的必经节点和顺序检查点，按显式避开/准入声明裁剪分支，构造满足声明条件的不重复节点计划。它不会先截取旧无约束搜索结果再筛选，因此较短但缺前置的路线不会占用合格候选的结果额度。

`RouteConstraintsPanel` 提供五个合成公开示例、可编辑JSON、选点添加约束/准入条件、显式缓存图导入、中文候选和停止前沿、可展开技术结果。`set_graph(graph, epoch=..., historical=...)` 只更新缓存并保留输入、选择、结果与滚动。`mapNodeSelected(str, object)` 使用与现有离线工具一致的 epoch、区域、模板、节点和坐标绑定；旧图链接会被拒绝。

输入中 `required_nodes` 指必须进入，`avoid_nodes` 指不进入，`checkpoints` 指依次进入；节点ID必须属于声明图。`qualifications` 按节点ID声明 `matches: true/false/null` 和可选 `reason`。不符声明排除分支，未知声明保留停止前沿并禁止推导其后续资源。起点已经是声明当前位置，因此起点的准入声明不被用于再次入场判断。指定终点若仍缺必经或顺序要求，仅列声明排除。

这些条件是规划者显式声明，未接入或证明游戏结局脚本。避开约束只指不进入节点，不定义加工品飞越路径。每条步行连线独立核算，封存的加工品/AP/一次性概念体账本在各分支独立使用；随机、未知次数、付款到零和到达AP未知沿用已有停止边界。战斗收益仍需独立关卡身份、所属层、入口和胜利声明，只显示已知基础分项。

来源见 [source-receipt.json](source-receipt.json)。本次没有引入新的数值或游戏机制，复用已有固定原表及社区结算来源。真实可达、当前服务器资格、完整奖励、失败概率、住民动态和真正最优仍未知。上限、缺项和未检查兄弟分支均保留，没有候选不能证明实际无路线。

# 路线续接与变化诊断

`continue_route_plan` 使用原计划、连续逐步进度声明与独立新图/当前位置/AP/库存，核对原余路和残余人工目标，构造新起点的有限替代方案。它补充静态方案之外的连续推进流程，不写本局状态，也不把名义预测当作实际资源。

只有与原模式/目标匹配且明确移动完成的连续前缀可以消解人工必经与顺序检查点。独立声明的graph.map_instance_id、区域/模板和节点ID/坐标需匹配新图当前位置；缺口、路径偏离、坐标变化、缺实例ID或同模板的新实例保留前沿。游戏结局前置与实际完成仍未知。跨区域时必须独立提供新目标及完整新人工要求，不自动搬运旧目标。

胜利、失败与移动完成独立声明。获胜不会填写未知移动，不自动扣/返AP、修改库存、完成节点或驱逐居民；失败后继续资格独立声明，否则停止自动续接。即使游戏文档描述某种转换，after图变化也来自单独声明，不由battle结果生成。

来源前缀的AP/次数预测与新声明并列。只有闭合前缀/锚定时求AP差值；实例缺失、新出现、未知或同ID原件身份冲突分别显示，不把差值解释成获取、消耗、热更新或机制错误。未知新库存/概念体不借旧名义状态补全。

原余路逐条核对新连线和实例；缺原连线时给精确步骤，不把多格最短路替换成一次原步骤。旧战斗身份不搬到新图，原条件与新实际战斗资格分开。替代搜索从明确新起点和残余人工目标开始，沿用固定几何/AP规则并保留步数、分支、结果上限与未证前沿。

`RouteContinuationPanel` 提供六个公开合成预设、原步骤移动/战斗声明、独立新当前位置及失败后继续资格按钮。设置后一步时，之前缺少的进度保持未知；按钮不更新AP/库存。显式缓存图导入只替换after图，before/计划/进度与新资源保留。地图绑定、刷新保留和旧输入结果警示沿用封存编辑组件。

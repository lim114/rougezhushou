# 居民路线分阶段候选核对

`review_resident_routes` 将有限显式方案中的每次玩家移动与居民声明快照相结合，按明确连线逐次展开一格居民候选。每步保留进入前、移动后，以及独立据点胜利声明后的不同阶段；它们不是实际执行顺序或碰撞证明。路线最多20条，每条最多10步，步行必须逐条相邻连线声明，不把多格步行缩成一次居民时钟。

没有未排除相邻目的地的候选分支不会消失：回退及后续位置标为未知，并持续传播。一个分支有已列位置、另一个分支回退未知时，两者同时保留。候选无交集不表示安全，居民之间的同步选择和碰撞仍未知。移动账本在付款到零、随机目标、次数或到达AP未知时停止居民移动推导；尾链明确未评估。

`resident_post_victories` 是独立的路线ID到获胜步骤列表，仅可绑定明确 `BATTLE_SAVAGE` 节点。移动声明闭合且调用方独立声明据点获胜后，按固定文档另列“条件驱逐全部居民”阶段。它不从抵达、普通作战或基础奖励推定获胜，也不改写实际本局。后续空候选只有这项胜利声明的条件意义；先前位置未知也仅在该条件阶段被驱逐。

`ResidentRouteReviewPanel` 提供五个公开合成示例、可编辑JSON、追加居民快照、选择步骤独立声明据点获胜、中文分阶段结果及技术详情。`set_graph(graph, epoch=..., historical=...)` 只更新缓存；输入、路线/步骤选择、结果及滚动保留。地图信号沿用首组的epoch、区域、模板、节点和坐标绑定检查。编辑声明后保留计算时输入快照，并标记旧结果需要重新核对。

原文及冻结属性见 [source-excerpt.html](source-excerpt.html)、[frozen-facts.json](frozen-facts.json) 与 [source-receipt.json](source-receipt.json)。直接复用并重读PRTS433770居民段落，不引入新的动态脚本、概率或隐藏资格。原文明确连通一格移动、具名重复节点/据点/玩家完成空地的排除，以及据点获胜直接驱逐；未规定回退与碰撞顺序。

验收见 [verification.json](verification.json)：13项行为与6项Linux Qt检查通过；包括混合已知候选/未知回退、未知居民在后续独立胜利阶段的条件清空、停止尾链、编辑快照保留和过期地图链接。实际Linux组件窗口1250×900已检查中文显示。原生Windows、游戏、当前服务器、真实安全与聊天联调均未由本回执验证。

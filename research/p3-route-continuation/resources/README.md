# 路线资源授予与独立出口账本

`route_resource_ledger` 将加工品希望/源石锭、概念体护盾/随机收藏品数量与基础战斗分项放在同一有限方案中核算，再接续独立出口阶段。结果保留来源数量、已知小计、未知或排除条件；这些数值不是实际收到、私人资源余额或完整收益。两条方案可看已知小计差值，同终点/转移且所列条件闭合时另给条件数量差值。随机品的品质、价值与具名池不可比，不作真实收益排序。

`activation_declarations` 按路线ID、步骤文字序号、概念体ID声明 `true/false/null`，不从加工品移动推定实际激活。一次性概念体明确激活时扣一次；未激活保留；可能激活使后续余次数未知，即使另一个后续节点类型已明确也不能再次确定领取。已声明激活却违反源资格/余次数时记录冲突，并禁止闭合分项总量。各路线独立复制预算，不共用扣减。

白模鸟的战斗后收藏品另需 `after_battle_declarations`，不从普通胜利资料推定这个结束阶段。战斗攻速始终只作资料，不进入本账本。随机收藏品只合计来源明确的数量，不生成池、品质、价值或概率。

`terminals` 独立声明转移和 `success_declared`。主区域出口必须与路线终点明确原类型一致；FINAL按原选项等量希望作1:1条件参考，首领兑换数量/比率保持未知。付款到零、随机目的地、未知次数/AP及停止尾链不资助终端授予。耗尽加工品从余持有损失中移除；M04/M07在主区域前进的条件损坏与秘境例外分别显示；M04原文明确进出，M07只明确进入，返回处置保持未知，不写本局库存。

`RouteResourceLedgerPanel` 提供五个公开合成示例、步骤/概念体选择、独立激活/战斗结束/转移声明按钮、中文来源账本与方案数量差值。缓存图导入、epoch/区域/模板/坐标地图绑定、编辑旧结果标记和刷新保留复用前两组的封存编辑器组件；不调用居民模型。旧移动模型的自动触发次数只是独立来源参考，本账本余次数采用自己的显式激活声明。

固定原件选择器、数量及出口原选项见 [frozen-facts.json](frozen-facts.json) 与 [source-receipt.json](source-receipt.json)。旧路线回执所指 `.cache` 未迁移，故针对M04/M07秘境例外直接查询PRTS引擎配件目录，保存434637版本 [parts-current.html](parts-current.html) 及 [temporary-parts-excerpt.html](temporary-parts-excerpt.html)。M04备注明确“不会因进入或离开误入奇境节点的特殊层而损坏”，M07仅写“不会因进入误入奇境节点的特殊层而损坏”；文档版本不证明当前服务器脚本。

必要验收见 [verification.json](verification.json)：14项行为及4项Linux Qt检查通过；实际1280×1000组件窗口已检查中文来源数量和条件说明。记录了资料回执准备时错误文件名的失败及修正，没有将其算作功能或产品验收。原生Windows、游戏、当前服务器机制和聊天联调未由本回执验证。

独立只读审核发现并修正了M07来源过度概括与合成库存ID碰撞，补入两项回归；初次错误概括及封存回执保留在 `superseded-before-source-review/`，不得当作当前来源结论。

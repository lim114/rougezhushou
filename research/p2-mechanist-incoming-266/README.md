## 已证算式及分支

FP原值单位为 `2^32`。`IsZero(v)` 使用 `abs(v_raw)<42950`；`LE(a,b)` 使用 `a_raw<b_raw+42950`。仅支持非负屏障黑板原值，负值拒绝而不夹为0；入伤值可为负。

普通路径资格独立声明：修改器未取消、属于伤害、未绕过 BLOCKED、对应屏障实例可用。模板关闭类型和施加方式筛选，闲置 PHYSICAL_AND_MAGICAL 字符串不作为额外限制。零/近零入伤会在入口被视作取消；负非近零伤害不能直接当无操作。

即时吸收为 `min(max(value,0),dynamic)`；分别从 dynamic 和修改器 value 扣除。剩余修改器值满足 LE0 时，BlockDamage 请求 BLOCKED 取消并设置 value=0。后续 CancelModifier 仅改变取消状态，不清零 value。因此“剩余数值10、取消请求成立”不能显示为真实生命损失10。

dynamic耗尽门之后，两次来源筛选只控制是否请求取消溢出：受击对象身上分别来自机械师来源与自身来源的盾。没有host/token身份替换，不包含第三方来源盾。来源缺失时模板允许该筛选通过；受击对象缺失不是这一分支。本体的两个来源身份相同，在声明无中间变化时输入须一致。

随后 AlwaysNext 保持流程继续，首次主buff查询控制爆炸请求；弹药读取后第二次主buff查询控制计数节点及补盾请求。两个查询分别声明，不以buff存在推导技能isAffecting。弹药读取失败会停在旧盾结束请求之前；读取成功则最终AlwaysNext允许请求结束旧盾。

计数节点外层返回与计数源是否存在分别声明：缺currentProgressSource可不扣弹，但外层返回true，仍请求补盾。isAffecting=false、ignore-until-cast-end=true或not-count-next=true也可耗弹0而保持补盾请求。最后一发正剩余弹药仍允许该次补盾请求，不能推出技能同帧结束。

## 连续账本与输出边界

顺序是独立声明，不推断同帧先后；本体/结构性原理共用一个无外部变化的条件弹匣。缺门、缺实例或外部弹药变化会使相关依赖结果未知。已证吸收小计与全部吸收参考分列；缺一项不以0补齐总量。

`no_intervening_barrier_changes` 仅声明扣减至后续读取之间无回调改变屏障；未声明成立则即时算式可保留，实际后续耗尽门未知。新盾创建和旧盾结束均只显示请求；下一包必须独立提供 `following_barrier` 或保留未知，不能凭CreateBuff请求自动建立新盾。未提供后续实例时不假定MarkFinish已完成移除。

`manual_count_node_success` 表示计数节点外层返回，`progress_source_available` 表示计数源存在，二者不可混用。`caster_shields` / `recipient_shields` 是相应节点读取时的筛选声明，不是把全部其它护盾求和。

不会求最终HP损失、实际爆炸命中/总伤、创建时最大生命快照、新盾成功创建、碰撞/补盾/结束时间；不写本局、不发送聊天或采集战斗状态。已存在声明总破屏次数/时窗接口不被自动覆盖。

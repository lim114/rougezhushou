Problem and supported domain

Combat.plan uses the explicit window to filter finite-ammo impacts in its frame
attack_times branch (operator_engine.py304–310). Its ammo branches keep their
nominal ammo-round interval horizon, however: AG S3 at888–889, Angel2 at1071–1075,
and Wisdel S3 at1104–1107. Combat.calculate currently publishes shown.duration as
observation seconds and divides the already filtered window damage/healing by
that shorter duration (1540–1543). The release-based full duration at1210–1216
and phase/cycle/SP clocks serve separate purposes and must remain unchanged.

The legacy finite-ammo paths have the same reporting mismatch: damage.py206–219
clips impacts to scenario.window_seconds, while estimate.py154–155 clamps its
observation denominator to full execution_seconds. The supported legacy cases
are mechanical S1 and medical S2. Medical S2's friendly fallback is real existing
code (damage.py128/131/228–229 and estimate.py142–153), so HPS reporting must
use that same stated observation domain even with an empty enemy.

The proposed scope is seven finite owner-ammo profiles: Angel2 S1/S2/S3, AG S3,
Wisdel S3, mechanical S1 and medical S2. An explicit window remains an observation
interval after the last ammunition release; it does not promise a repeated cast
or newly scheduled post-skill damage. Without an explicit window the original
presentation is retained. Existing invalid-window validation, caller ownership
and all hit/cast/phase/cycle/SP behavior remain original.

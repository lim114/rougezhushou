实际作者基线为 full90 commit 2cbc45f03f99ed4f04b9c7e2612b58542f909168 / p2-validation-090。两目标文件与此前 5e2ff 的固定对象逐字节一致。原 source34 和旧 design8 保持历史原件；旧 design8 的“不增加 toggled 刷新”范围被本次明确授权扩展，不能把旧计划改写成已执行。

问题一：自然回复技能的持续普攻条件被隐藏。

app 原949–960从当前选中技能和当前培养所选技能等级取得 sp_type，但只对 INCREASE_WHEN_ATTACK 显示该行。已封源证据中，阿米娅 E2 情绪吸收、近卫实际适用的攻击回技力藏品可在自然回复技能消费持续普攻条件。因此对已实现干员、当前有效所选技能的 Attack 或 Natural 类型显示原有同一控件。未实现干员、占位/无技能及其他 SP 类型保持隐藏。这里只判定条件行可访问，不判定天赋/藏品是否实际适用；不会依据原始藏品 ID、最终 cycle 是否变化来推导活动资格。

问题二：输入改变后旧结果可能仍显示。

原566–568只有建立、默认 True 和表单行；连续复选框未连接计算刷新。新连接放在现有 setChecked(True) 之后，采用原 OPTIONS 布尔控件666–667的 toggled.connect(lambda:self.calculate())。既有 calculate 数值入口、错误和报告路径逐字节/AST保持；无新增后台消费者。源码只能证明 setter 先于连接及文本连接模式相同。实际信号发射、初始化和复算次数由 root 真实 MainWindow 测量；技能/培养切换原本存在多个刷新入口，不能承诺一项操作只有一次 API。

问题三：行名和提示不能暗示自然回复必有额外技力。

表单行改为“普攻回技力条件”，复选框原名及默认值保留。固定提示说明“自然回复技能也可能通过适用的天赋或藏品使用此条件”，同时明确“显示此项不表示必有额外技力”“未核验的技力来源仅作资料参考，未知回转保持未知”。此提示不赋予新 SP 来源、时序、击杀、受击、元素损伤或原生技能绑定资格。

问题四：既有实际窗口验收仍用旧 Attack-only 合同。

scripts/verify_damage_ui.py 原39仅期待 Attack 可见。本次只迁移这一表达式为 Attack/Natural，并从实际选择的 skill_rank_value()-1 读取 SP 类型。循环原先已排除未实现干员，catalog.operator_profiles 对已实现条目覆盖为同一 catalog profile；其余验收字节保持。没有执行旧断言失败，亦没有产品失败。此改动是既有验收合同迁移，不新增文本镜像测试。

保留条件与未知边界：

- 原 QCheckBox 身份、setChecked(True)、isChecked() 原生 bool 序列化和所有隐藏状态值不变。没有新 reset、培养迁移或设置持久化。
- row 可见不保证倍率、回转或额外 SP 改变。银灰无适用额外来源、古米及118仅资料来源均需要保留旧边界。阿米娅 E0/E1 没有 E2 情绪吸收的攻击信用；参考标记不能当新 bool 数值实测。
- placeholder/未实现/无技能在 scenario 和数值 API 前早返回，但 calculate 之前仍清结果和同步动作/个人强化；不能称整个路径零 helper 或无副作用。
- “形态”验收只使用 app 现有可选干员条目/既有培养记录，不增加转换按钮、原生转换或技能绑定机制。其他 SP 型保持隐藏；source34已证 Hsgma2 S1 为受击型、Yato2 为数值8，后续使用 actual 冻结源确认合法所选培养。
- P1 暂停，识别最后。受击/事件和未知原生 clock/reference-only 继续由既有后台标注。此次 UI 不把任何 reference-only 升为数值来源。

# 两张固定原图的低地道路逐格参考（288）

新增“陌生旅伴”8格、“开业剪彩”4格，分别绑定3个原始关卡ID。
只收录两位读者从原图独立读取、相差不超过4个原像素的12个格中心。
其余11个待测格未通过，保持未知，不平均读数、不调整位置、不降低门槛。
现有28格及全部12张常规平面资料未改变。逐格参考合计8图、14关、40格；
整图平面未校准范围仍为81关、59张独立原图，不能把逐格增加计作整图完成。

这些是低地木路/地板的近似中心参考。高台顶面、入口立体框的脚点、出生偏移、
随机范围、实体实际位置和到达时间仍未核验。原图仅显示已核对的整数格中心，
不从原图反推格子，不外推其他格，不把已知两端连成未知的中间路线。

新道路点显式写入 `tile_key: tile_road`，并要求原格资料为 `LOWLAND` 且类型
相同。新地板点显式标记 `tile_floor`；旧点缺省标签仍仅代表旧地板。
缺少道路标签、标签类型错误、类型不匹配、高台或其他格类型都不能获得映射。

## 来源与原始失败

`source-manifest.json` 封存13份公开原件。`author-readings-before-fit.json`
在第一次拟合前冻结作者读数；`independent-readings-before-comparison.json`
为另一读者未查看作者像素/矩阵时独立读取的结果。`blind-source-request.json`
只提供逻辑格、原图和像素刻度图身份，没有作者坐标。`point-comparison.json`
保留全部23组距离与接纳/拒绝结果。运行时使用未修改的作者原读数，第二份读数
只用于逐点一致性检查，不取两者平均。

`first-failed-regular-fit.json` 原字节保留两次首次平面失败：
“陌生旅伴”最大误差5.216400541309983原像素，“开业剪彩”4.958574758473317。
两者都超过4，未升级平面、未修改点。`unpublished-direct-center-delta.json`
与 `INTEGRATION_NOTES.md` 是集成前准备原件，名称和当时的“尚未发布”状态
照原样保留，不代表当前程序缺少本节已经实现的功能。

两张原PNG和两个原始关卡JSON可直接核对。固定来源是项目既有的公开提取原图与
游戏资料版本，精确URL、SHA256、资源Blob SHA1、图像尺寸与各别名绑定均保留在
原始源文件中；本节没有将原图替换为视频截图，也没有使用当前游戏画面。
`source_file` 内旧 `.cache` 路径仅说明历史来源；重放不读取这些历史路径。

## 重放与验收边界

只读重建：

```powershell
.venv\Scripts\python.exe -X utf8 scripts/extend_direct_landmark_288.py
```

显式写入当前工作副本的固定逐格资料：

```powershell
.venv\Scripts\python.exe -X utf8 scripts/extend_direct_landmark_288.py --write
```

构建校验全部封存源文件、原PNG/Blob、原关卡JSON与逻辑网格、每个别名、两次
失败平面的数值重放、23组原始读数及未修改的既有参考。写入只接受封存的旧版本
或相同构建结果；发现其他并发修改即拒绝覆盖。

`tests/test_direct_landmark_288.py` 覆盖原点保留、11格拒绝、12格真实解析、
标签/类型/高度及来源失配拒绝、严格4像素边界、只读/显式写入、源文件篡改/缺失、
3种尺寸缩放、逻辑格点选/刷新、未知不画、原图不反算及不连线。
独立Qt控件验证不等于实际Windows主窗口或游戏内实测；后者按根验收回执单独记录。

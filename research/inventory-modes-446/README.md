# 第446节 + 重复热水壶件数、合并与图文卡片切换

基线 `48712c7e453de4e23b542a509b69543137a168ed`。本节交付新的持有件数与显示能力，不是仅更换主题。原片保留本机，不分发影片或截帧。

## 先纠正需求前提

实际回看本机原片166秒、174秒和170秒页脚，页脚写的是“合并重复热水壶”，不是合并所有同图、同名或分档藏品。166秒为图标、名称和效果并排的三列卡片；174秒为大图标网格。提取时核对影片SHA256 `0b83e44f0816508ef095120961496337e6bd65d5f531ee350c078950dfb98bda`。这是定点回看，不声称本轮连续看完整片。

[PRTS热水壶](https://prts.wiki/index.php?title=热水壶&oldid=434529)明确黑流树海的效果为目标生命上限及希望各增加2，收藏品池耗尽后的补位品可重复持有，上限100；其它主题的效果不能套用。固定游戏包准确条目为 `rogue_6_relic_legacy_1`，当前名称、图标和效果另行核对。上限来源仅作机制依据和边界案例，不按猜测截断读取数量，也不由持有件数倒推当前资源。

## 已发现的问题与实际改动

原实现保留五个明确图标槽位（三热水壶、一薄行囊、一道具），却按不同身份计为两件收藏品，完整性因此错误。改前隔离重现见[before-counts.json](../../verification/sections/446-inventory-modes/before-counts.json)，不使用私人状态。

完整且每格已确认的图标栏现在可证明热水壶的重复件数。收藏品物理件数、不同资料身份、道具件数分开：本例收藏品4、道具1、合计5；计算器仍接收不同身份一次。原来健康的完整单件记录可以证明一件，但不能由合计差额反推重复数量。局部、歧义、过期或不一致记录仍标件数未确认。同局复用和重启沿用已存在的图标栏记忆，不增加新存储格式、不补造领取事件；当前完整证据的缺席标记仍保留旧记录和历史，只有用户手动重置才清局。

“合并重复热水壶”仅改变已读持有列表的显示：展开逐件，合并显示数量，始终保留准确资料ID。全部资料目录仍每身份一项，其它同图或分档不合并。选择、效果阅读、来源卡和刷新继续有效；数量未知不补造重复行。

收藏品、道具、零件和商店的显示滑块向左为图文效果卡，向右为图标网格，按实际可用宽度重排。完整原文仍在资料和侧栏；卡片省略处使用明确省略号。敌人图册等未启用描述卡的目录保持原样。商店价格不因切换消失。窄窗页脚按Qt实际尺寸换行。

## 外部成熟方案与本地代码的界线

本项目优先复用他人的成熟代码，而非只整理内部控件。前批真正接入的[PyQtDarkTheme2.1.0静态QSS、完整调色板和SVG](../player-theme-20261101/README.md)及[Qt官方BSD Flow Layout](../../rouge/flow_layout.py)继续用于生产；许可、固定版本与本机适配证据沿用原件。本节文字排版直接使用Qt的[QTextLayout](https://doc.qt.io/qt-6/qtextlayout.html)和[QStyledItemDelegate](https://doc.qt.io/qt-6/qstyleditemdelegate.html)，不另写文字换行引擎。但使用Qt接口不是又采用了一个外部项目，重复热水壶和现有状态的连接仍是本地胶水代码。

MaaFramework及PyQt-Fluent-Widgets的调查、许可和隔离识别结果见[445研究](../source-nodes-445/README.md)；本节没有将它们接入生产，也未取得参考视频程序的源码。完整Python源码按源文件直接审查，本轮没有新增REA工具调用，不把静态审查冒充全程序逆向完成。

最终数量以[本节回执](../../verification/sections/446.json)为准。当前范围覆盖完整件数、未知不猜、部分读取不删记忆、明确完整栏更新、重启、100件边界及临时手动重置、合并与展开、资料身份及来源操作、图文/图标切换、阅读保持和多宽窗口。全部游戏数据使用公开隔离夹具，禁止游戏控制及测试聊天；普通测试窗口另行更新打开。

# 探索地图叠加显示修复

本批只修已有叠加的启用、配准和参考帧更新，不增加界面元素或改变绘制样式；功能节数保持472。

## 已核对的原因

旧会话448次叠加检查均为关闭状态。原构造函数默认关闭，设置复选框未恢复或保存开关。现在没有保存值时默认开启，用户保存的关闭值继续生效；开关单独保存于本机`.local/player-map-overlay.json`，不改聊天、快捷键或本局文件。初始化不写设置，损坏文件保留。

开启后的实机基线仍未显示：54条记录中，44条被图标中心像素变化拒绝，10条尚无参考。当前源码已交替处理最新和较早候选，旧会话的纯排队现象不能直接当作当前实现。

## 改法与取舍

- 当前OCR提供节点文字区域，按原始画面坐标映射一次。保留标题逐字节核对，节点改用同位置文字结构核对，先减去缓变背景，再用OpenCV归一化相关性和对比度核对。仍要求标题及至少三个节点；不足时保留原中心像素核对。
- 同一区域探索页暂时识别为多个模板候选或节点文字不足时，不替换上一份参考。该参考仍须通过当前画面、窗口及原30秒时限的核对；没有续写拍摄时间。其他页面或区域照常替换。
- 自动采样保留最新/历史交替与按拍摄顺序合并；地图参考满20秒时优先识别一份真实最新帧，也能读取被去重的静止画面。历史候选仍排队补记；容量上限不变，过载淘汰和全程短页完整性仍属待办。
- 原30秒参考帧、2秒当前帧、游戏前台、窗口身份、客户区尺寸和同局条件均保留。缩放后先隐藏，等新尺寸识别和配准。未选节点类型时允许显示既有标题，节点圈注仍由已有类型选择控制。

实现复用现有OpenCV与Qt，不引入新依赖。方法依据：[OpenCV模板匹配](https://docs.opencv.org/4.x/d4/dc6/tutorial_py_template_matching.html)、[滤波](https://docs.opencv.org/4.x/d4/d13/tutorial_py_filtering.html)、[Qt原子保存](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QSaveFile.html)。本机画面对比用于选择区域和检验参数，不作为跨场景覆盖证明。

## 验证与记录

定向检查和本轮实机结论见[维护回执](../../verification/maintenance/map-overlay-display-20261103/summary.json)。原失败与所有实机日志、图片只留本机`.local/gate0/`；公开回执仅含范围、汇总数字和源码摘要。窗口显示时点按原生窗口可见性记录；撤下延迟从独立画面有效性检测起算，含轮询误差，不当作鼠标操作到屏幕像素的精确时延。

大窗口65秒静止记录在首次显示后没有中断；切页后撤下并恢复。800×600约62秒静止记录首次成功后持续显示，但随后延长记录又出现3条参考过期，连续性仍未通过。最终尺寸调回后恢复；末次尺寸变化至下次显示约36.52秒，包含设置/切页过程，不能当作纯识别耗时。独立检测到隐藏最长约1.714秒，另有轮询误差。这些缺口保留在待办，不以恢复过一次销项。

最终调度修正后，2048×1080热状态连续65.06秒，50条叠加记录全部可显示、无撤下，237次前台检查均为游戏；当前页结果接收年龄中位2.30秒、p952.62秒。冷启动记录首次显示8.99秒；热状态已显示不当作冷启动提速。该轮仍有486个候选被容量淘汰，不能按候选数推断丢失页面数。

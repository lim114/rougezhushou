# 连续体验推进流程（最终版）

2026年11月2日用户确认。取代按P3广度持续扩展的执行方式；既有功能与剩余要求保留。先记录真实使用，再修闭环，再收拢入口，最后补功能与外观。不承诺固定周数，不增加功能节数来计入记录、研究或维护。

| 阶段 | 工作 | 结束条件 |
| --- | --- | --- |
| Gate 0：口径与记录 | 一页规范、轻量本地记录、运行时表面清单；正常流程、转场动画、缩放遮挡三场约10分钟真实会话；三个定向场景 | 能解释主要失败及影响；同一输入的记录开销可比较；未出现的场景保留待验证 |
| Gate 1：修主要原因 | 按Gate 0结果优先解决两项高影响原因，同根因合并，必要依赖一并处理 | 对应场景连续完成，必要定向检查通过 |
| Gate 2：收拢入口 | 复用现有共享资料窗，核对黄金路径入口及状态保持 | 入口齐全，刷新不打断阅读；实际可见表面不超过基线，再按使用结果确定目标 |
| Gate 3：补功能与外观 | 工具条、地图叠加、悬停卡、通知、统计卡，逐项对照视频 | 每项有相应实机演示与对照，未达到项明确保留 |

Gate 0期间只加记录、尽量保持产品行为；黄金路径外新增功能冻结。是否继续P3资料覆盖、调整OCR或重构界面，由首轮实测决定。每道门禁均可停。体验以连续真实会话为主，回归用定向检查，机制与数值用资料和独立算例核对，三类证据分别保存。全量检查继续取消。

黄金路径：启动 → 绑定游戏 → 工具条 → 地图叠加 → 游戏藏品悬停卡 → 主窗本局藏品 → 笔记 → 隐藏敌人通知与统计卡。最后两项按实际进程分别录制；3分钟不剪辑录像用于最终展示。游戏信息自动读取，点击助手、切页、写笔记属于正常操作。仅读取游戏，不操作游戏、不改变焦点、不上传个人数据。

状态规则：当前已读正常显示；资源等可变化数据保留上次确认值并附时间；同局已确认的分队、难度等稳定信息继续正常显示，遇新局或矛盾再处理；从未读到显示“—”，不适用隐藏；0正常显示为0。读取失败不清除同局已确认值。

验收记录包含关卡、层、难度、队伍、是否同局及运行环境。指标分页面与切换检查，记录关键字段读对/漏读、变化后的更新延迟、失效撤下延迟，以及跨局/页面/干员/节点错归属。录像人工对照提供真值；探索叠加与战斗隐藏敌人分别判定，记录误显、漏显、错节点、错关卡。

叠加候选方案：局部匹配、缩放后重配准、静态参考续验分别验证。内容识别与有效性续验分离；记录识别帧、最近通过核对帧、最新采集帧时间。续验必须对应新鲜画面；定期完整识别的间隔由实测确定。少节点方案须通过相似地图反例。Gate 0不先更改现有阈值。

记录器复用现有采样、计时与路由，异步写盘；同一输入预热后比较开启/关闭记录的中位数与p95，另核对实机流畅度。规范、脚本与测试进Git；日志、截图、录屏和对局内容仅在本机`.local/gate0/`。保留至本轮复核结束后由用户手动清理，不自动删除或上传。默认日志不保存原图、原始OCR、笔记、聊天或凭证。

每道门禁交付：文件与行为清单、定向检查、真实会话时间戳与问题、尚待验证范围。`VIDEO_PARITY.md`改为按可单独验收效果组织的矩阵，区分已实现／待实机验收／未实现；旧记录归档，不强求行数。

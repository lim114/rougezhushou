# 存量整改：编辑器单次解析、初始化与异常边界

本轮修改6个运行模块，仍为维护，不增加功能节数。源文件和哈希见 [summary.json](summary.json)。本轮没有新增低概率防御代码，没有修改游戏叠加、公式、路线信息范围或私人状态。

## 已完成的修改

- 收窄16处 `except Exception`：编辑中的JSON结构错误仍按原流程处理，内部RuntimeError不再被当作输入错误吞掉。后台任务向界面返回异常的边界保留。
- 三个继承页面先创建自己的控件和示例选项，再加载一次示例。删除两处初始化判空、三个“找不到选项就取第一项”的补偿，以及重复的JSON读取/写回实现。
- 同一次联动刷新传递已解析的输入：居民、资源、情景页面从3—6次解析降至一次；离线查询启动从两次降至一次。有效输入、尚未完成的JSON都验证过；独立入口仍自行读取。
- 沿用Qt控件、Python标准库JSON和已存在的处理方法；没有新增抽象层、依赖或页面功能。历史诊断工具没有重新接入玩家界面。

## 验证

最终39项定向检查全部通过。覆盖公开示例、编辑后结果失效、旧任务不覆盖新输入、选择/阅读位置保留、独立导入、初始化顺序、非法嵌套输入、单次解析以及内部错误传播。未运行全量。

修复前，新测试实际复现了提前访问控件、吞掉RuntimeError、同次输入重复解析。初次离线伴随测试误用了不存在的查询，修正测试为现有compare入口后，再复现两处吞错；该测试设置错误不记作产品缺陷。全部原始运行日志保留在本机 `.local/code-constraints-review-03/`。

本轮测试证明上述调用路径，不表示六个模块的所有代码均整改完成。全程序覆盖采用 [增量清单](module-delta.json)，引用上一批已冻结清单，避免重复复制整份清单。

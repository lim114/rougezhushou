# 维护：追加观察一次验证并取消无用诊断计算

旧追加流程先完整诊断原声明，再追加一行后完整诊断一次，结果全部丢弃。现同一诊断入口接收原声明、新观察与当前干员，检查父结构/归属/培养/容量，再一次检查各行；全部成功才返回声明写入编辑器。已有观察仍需至少1项，追加后最多32项。原输入和新观察不被修改。

追加使用validate_only：完成输入校验后不运行原商数、二分查找或组装完整报告；点击计算仍走原完整流程。没有新增单次包装。中间版只将完整诊断2→1，测试进一步发现仍有54次不使用的数值计算，已消除并保留该失败记录。

19项定向通过，覆盖成功追加、跨干员、重复标签、容量、坏整数及坏声明，失败时编辑器和已有结果不变。9组有效追加报告与旧版一致，66组无效追加拒绝类型一致；全部75组的仅验证模式与完整诊断接受/拒绝及声明一致。普通183份报告和文字、24种错误结果保持一致。数值主体未改，未跑全量。

多重错误的提示优先级有变化：三个干员“空观察列表+作用域不符”现在先提示作用域，原来先提示列表长度。仍拒绝且不改内容，不把错误文字顺序计作完全一致。对照脚本首次复用旧AST选择器失败，已改为比较当前HEAD已有的共享计算主体；没有为通过脚本改产品代码，记录保留.local。

完整阅读界面与MainWindow调用，set_context确实接收None，是正常无情景输入。D150两处宽异常出口原样登记；累计113组待审。两个模块普通回顾完成，防御仍待审。后续继续主计算与受疗资料培养准备、阶段类型契约及其它未审模块。

测试窗口已更新、可见响应；组件操作由隔离Qt定向检查验证，不冒充游戏实机验收。截图和原始日志只留.local。维护不增加功能节数。

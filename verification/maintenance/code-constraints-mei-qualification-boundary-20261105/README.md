# 维护：梅独立查询与参数入口统一阶段准备

独立界面查询原来先找模组、验证阶段、取条目，再调用参数层重复上述准备。现先严格找一次模组，把已找到的对象交给共享参数入口一次处理阶段、培养与条目；同时返回参数与原目录条目供原生绑定使用。模块扫描2→1。计算收尾继续复用主计算参数，没有恢复重复读取。

内部reference现在直接返回参数与目录条目，两处实际调用方直接拆分；玩家报告形状保持。显式None/空条目仍表示无资料。不保留单调用适配包装。模组缺失、假值等级、条目归属、原生绑定保护未删改。

29项定向通过；新旧110份完整报告、4种计算错误、378组独立资格查询、840组公开参数查询一致。输入不变。改前新增检查6项中1项失败，模块扫描2次。内部返回契约切换时1项测试仍按旧字典取值而报错，已同步解包并保留输入/目录不变的原断言；失败日志保留。没有全量检查。

边界变化单列：直接手工调用qualification并同时传入精英99、等级None、模组阶段0，旧版在阶段门槛提前返回，现在参数层暴露IndexError；不新增兜底。实际两个界面调用均由training_conditions传入等级控件数值，不会传None；计算入口仍验证培养。此异常组合不计入378组一致结论。原固定目录缺模组时，界面的严格next行为仍保留，未借共享函数新增静默处理。

两个模块的普通规则回顾已完成；D138/139及新增D141/142等待审核，不作整模块销项。待审共105组。下一批转向其余计算/资料模块和调用入口，普通剩余不转成待审。

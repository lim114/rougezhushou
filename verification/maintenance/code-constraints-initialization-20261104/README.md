# 存量代码整改：先完成控件构造，再首次刷新或计算

本次维护不增加功能节数。第473节保留原有交互缺口；全程序整改仍在进行。

## 实际修改

- 19个事件子页面先建好自己的条件、奖励和后续选项控件，再首次读取资料。独立使用的父页面保持原有首次读取行为。
- 最近关卡页、补充干员计算页采用同样的初始化顺序；首次刷新和计算不再访问尚未创建的子类控件。
- 24个运行模块中的41处 `getattr/hasattr` 调用已移除。确实按事件类型创建的控件，直接按事件类型读取；未知数值和资料失效仍按原来的业务状态处理。
- 移除仅为“控件可能没创建”服务的内部取值函数，不新增包装层、不改公式、资料口径、游戏采样或叠加交互。
- AGENTS.md和项目要求明确：新增低概率防御必须先解释并取得开发者同意，不得以“必要”自行豁免。本轮没有新增此类代码。
- 用户远端27740372a中的叠加命中修改、已删除旧验收均保留。`player_game_map.py` 未改。

三个父类增加的延后首次读取/计算参数用于明确子类构造顺序，是正常初始化流程选择，不是捕捉异常或补充容错。无需新增第三方组件。

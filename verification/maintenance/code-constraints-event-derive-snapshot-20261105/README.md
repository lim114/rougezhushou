# 维护：事件目录构建复用同次来源快照

derive原先先读取来源构造事件快照，之后再读取一次来源补选项。现在普通事件和附加事件都在第一次读取后立即生成选项，快照、正文和来源身份来自同一份ref；不缓存整批provider对象，也不新增失效/恢复策略。两条实际构建路径共用_entries，替代把27行选项生成复制两遍；此函数有两个实际调用点，不是单次包装。原文选项和物品表移到事件循环外，同一非空场景标题只计算一次。

修改前定向检查确认39个事件各读取2次，生成目录内容本来与固定资料一致。改后来源读取78→39，场景标题计算277→137；39事件、277条选项、38旧分组及完整输出与修改前和固定JSON完全一致。这些是构建调用计数，不是玩家端识别速度或内存占用测量。

# 维护：面板与时序共用一次预测及汇总去重

timing_reference原先先调用面板预测，再以同一规范化条件重算伤害。现面板与时序使用同一个内部计算结果，首批三人九个技能每项2次降为1次。_panel_calculation承接原面板生成和完整计算，两个真实调用方共享；panel_layers保持原公开签名和面板格式。没有对外暴露额外计算数据，没有新缓存。

时序汇总只判断一次已读列表，最大/最小值各计算一次并复用；空记录仍返回未知。原计算顺序、输入检查、异常出口及精度规则保持。公共函数用于面板投影，内部函数有两个消费者，此抽取用于消除重复执行，不是单次薄包装。

改前2项检查中1项通过，另1项9个技能子项失败。预测复用后47项定向通过；随后汇总去重，重跑相关19项通过（包含在前述范围内，不相加为66项）。24份完整报告修改前/中/后相同，另6个藏品条件的旧新时序参考相同，输入未改。报告包括9组面板/时序、3组精确时刻、3组界限校准、9组时刻实验；均为公式/声明输入验证，不是游戏实测。

timing_calibration整份源码已逐函数回顾。时钟与周期解析是独立领域逻辑；记录身份、跨周期顺序、帧单位转换和充值/释放适用条件各验证不同契约，不机械删除。_number的OverflowError由超大JSON整数实际触发；ValueError捕获单独登记D112，未经批准保持不变。该模块仍不计整模块通过，其他calibration路径仍需继续。无新增保护。

原项目测试窗口已正常重开，工具条可见、响应；截图/日志留.local。代码、断点及索引同步，维护不增加功能节数。D38—D112共75组待审核。

本次使用已有Python计算管线做局部共享，不新增第三方依赖；外部方案不能代替本项目的面板/时序数据契约。

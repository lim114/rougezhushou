# 有限值保护边界：独立静态子审

固定来源 `2dfd9fa2c9a62db0112bc0fb98cd23123dd3b48b`。仅读取作者保存的 findings、18 个入口/保护摘录和 fixed-public 原代码；复核摘录对应实际 AST，检查保护和旧错误先后，不导入或调用任何项目代码。API、项目 helper、测试、Qt、Wine、矩阵、产品草案与 tracked 改动均为零；未重审第 86 节布尔字段或旧模组资料。

检查范围内已有有限值入口：两引擎的基础攻击/敌人防抗/窗口及效果值，实际消费的 option，legacy estimate 非负参数，时序标量和范围端点，藏品条件及有属性 rune 时的原生数值转换。身份/技能/培养先于引擎；固定敌人端点源码在身份验证后覆盖手动防抗。整数 raw-bool 检查受 owner/capability 资格约束；不能从此推广到所有非整数输入，也不能用没有实际消费的字段制造缺陷。无 rune 路径不经过 `_fp`，但仍有后续引擎入口。

NaN/inf 入口保护是源码结论，没有新增运行证据。有限输入不能证明派生乘积/求和永不 overflow；`_single`/`_fp` 的有限值及范围入口也不证明全产品派生算术安全。此负审没有确认具名缺失保护，不构造产品修复或编号小节。

本子审只读到 `_prepare_damage` 与 `resolve_enemy` 两端；作者保存包没有 `run_modifiers.py`，因此中间 `prepare_run -> resolve_enemy` 桥接不由本子审独立证明。父审可另从固定 Git 对象补证。历史 number-type 和零寿命别名回执只作已有记录，不称当前重新运行。

完成后释放槽位。只有具名实际消费字段、明确缺失有限值入口，以及已保存或另行授权的公开行为证据，才有重开依据。

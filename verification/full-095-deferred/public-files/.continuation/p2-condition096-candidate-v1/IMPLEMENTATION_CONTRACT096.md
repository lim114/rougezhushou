# 第96节：现有条件控件的培养来源说明候选

候选提供一组连贯的可见说明：6位干员、9个现有条件字段，对应7个命名天赋。每条说明区分当前测算已选中天赋、未选中天赋、暂缺来源，并分别标注精英阶段、等级、潜能及相关模组字段来自本局确认、账号参考或未确认预览。手动等级覆盖独立标注。培养资格与当前勾选/数值声明、实际触发和账号任务解锁分开。

| 干员 | 现有条件 | 命名天赋与范围 |
|---|---|---|
| 黍 | 三种职业、三名同职业、四名岁 | 天有四时；周期技力时钟继续未知 |
| 苏苏洛 | 受疗者初始费用≤10 | 微创治疗；已选潜能与模组候选来源 |
| 焰狐龙梓兰 | 强击瓶覆盖、上次部署附近 | 强击瓶专家从E0开放；翔虫机动从E1开放；普通/蓄力路径与部署时钟边界保留 |
| 伊内丝 | 已偷取攻击的存活敌人数 | 影织；人数仍保留原解析/校验 |
| 水月 | 存在半血以下敌人 | 第二天赋反移情；其它隐藏能力不充作其来源 |
| 斩业星熊 | 当前生命比例 | 鬼之架势；已有曲线与独立条件资料输入均保留 |

`rouge/condition_cultivation.py` 调用既有 `selected_talents` 获得当前命名天赋，才判定资格。基础候选以返回对象与真实 profile 中固定天赋/候选位置的对象身份定位，再严格核对原件投影；模组候选使用实际返回 parts 列表与当前模组阶段的对象身份，按原件 part 顺序和最后合资格 candidate 覆写定位固定 talentIndex。对 name/description/values 及原件 candidate 做递归类型、顺序和 float.hex 精确检查。参数为零仍属于有效已选来源；坐标或类型不匹配则标记来源缺失，不编造原件归属。

资料文件原样保存六位干员的完整原件 talents、八个模组的完整 metadata 及二十四个阶段的全部 parts。普通说明只显示有用的天赋、模组与培养来源；原件URL、哈希及原始描述留在结构化资料。说明对象深复制受控天赋/原件片段，不深复制 AccountCache、RunState 或无关 opaque 调用者内容。

界面在现有条件行后添加一个换行说明行，各字段拥有同样的 tooltip。培养/干员/技能变化沿既有 `update_skill_options` 更新；九个原控件额外连接仅刷新说明的 slot，确保勾选、人数和比例变动后文字跟随。原信号连接、calculate、输入默认值/范围、行可见性及 enabled 状态原文保留。构造早期先检测说明行存在，再访问控件和选择器。总览、无技能与不属本组的干员不调用选择器。

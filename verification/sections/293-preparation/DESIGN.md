# 安眠一隅：按当前阅读选择集中查后续

仅后继P3设计，未启动功能节、未提升代码、未运行Qt或测试。只在本缓存写入资料/方案，没有修改生产、研究公开包、文档或私人状态。既有完整场景文本、九条子边、奖励原文及292作战筛选不重复计成果。

## 新增能力与非目标

玩家不再需要从十二个场景的全文自行来回寻找结果：选择要查的那条“四处看看/触碰图案”资料后，一张卡集中列出**本条选择的文档所列后续、后续场景按钮及按钮写明的奖励**；可手动打开相应社区场景全文。未来按钮与本次选择分两层显示，互不相加。

这里“本次”只指玩家正在查看的资料选项，不表示已读到游戏当前按钮或已经执行。卡不分析走法，不推荐奖励，不折算期望，不计算概率，不清除旧未解析标记或25/57入口缺口，不修改资格/库存/RunState。源码目录和`choice_resources`等原引擎不改。

## 单一小接口

建议新模块 `resting_corner_results.py` 只暴露：

`resting_result_cards(event_id) -> {status, cards, sources, notice}`

- 非精确`community_group_023`立即`not_applicable/cards=[]`，不扫描来源。
- 来源有效才返回四张卡；卡用完整社区scene_key/choice_key定位。相同“触碰图案”及同文原候选不能互用。
- 来源无法核对返回`unknown/cards=[]`，保留现有原文入口；不调用注入的公开evaluator/data，也不让调用方覆盖source。
- 每外部调用核对完整资料包当前字节；允许按相同字节复用解析，不能跨查询无条件信任暖缓存。运行时只读精选原记录/本地完整HTML及固定目录，不读17MB大表；构建器复核固定完整大表和精选extract对应。
- 返回值深复制；不接受声明“本局已发生/已领取”的参数，不据用户持有反推随机分支。

最小卡形状（字段名为设计建议，不是既有API）：

```text
{
  reference_id: 完整choice_key,
  event_id, scene_key, choice_key, choice_title,
  scene_number: 按目录显示的1起序号,
  source_annotation_text: 精确原注,
  documented_count: 3或2,
  listed_branch_count: 3/2/1/3,
  count_matches: true/false,
  full_actual_pool_known: false,
  actual_selected_branch: null,
  actual_reward: null,
  branches: [{
    branch_id: 原choice:key:sub:序号,
    label: 小狗/捕梦网/松鼠/果园/竞速比赛/动物泥偶,
    target_scene_key: 同事件的精确社区目标,
    target_scene_number,
    target_scene_description,
    future_buttons: [{
      choice_key, title, description,
      quantity_reference, resource或category_text,
      game_choice_ids: 原样保留,
      game_match_basis: 原样保留,
      actual_granted: null
    }],
    actual_transition: null
  }]
}
```

这里只提取一跳，不递归把未来随机选择展开成领取序列。`1件珍贵的加工品`保留完整分类文字、quantity=1、具体物品/完整池未知；不能把“珍贵”硬编码成某个数值稀有度，也不能拿全部加工品集合代替池。99锭行只作**社区后续按钮数量参考**：`game_choice_ids=[]`、`game_match_basis=destination_mismatch`原样保留；同文原`choice_ro6_surprise_12`只能放依据页为不具来源绑定的对照，绝不补入IDs。

## 默认玩家卡与手动场景阅读

建议单一**非模态资料窗**，主面板只对安眠一隅显示一个“查看随机选择的后续资料”入口，不再增加几排主面板控件。无需新增离线query或battle API。

- 若292的具体选项筛选精确落在四卡之一，打开窗时可带入这个阅读引用；否则窗内下拉默认“请选择要查的资料选项”，不自动认定第一张是本局所处。
- 窗内以完整key保存四条选择，标签为“场景2·四处看看”“场景7/10/12·触碰图案”，不用同名或原choice候选匹配。
- 首个页签“可能的后续”展示集中卡。开头固定：“以下只是你正在查的选择资料，尚未确认本局已进行。各项是不同的可能后续，奖励需要在相应后续按钮中另行领取，不能相加。”
- 每项示例：“小狗 → 后续场景3；该场景按钮‘抚摸小狗的脑袋’写明20希望；本次是否看到、是否可选、是否领取均未确认。”
- 同页提供分支下拉（默认“请选择要阅读的后续”）和“阅读所选场景原文”按钮。只有明确同事件target才可启用；点击重新获取/核对来源后切到第二页“所选场景原文”，只呈现该场景的完整描述和所有按钮。按钮不叫“前往/领取/执行”，不借原nextSceneId代替社区链接。
- 第三页“资料与依据”保留原注、完整ID、两版来源和99锭冲突详情。普通页不用rawID、URL、sourceScene、destination_mismatch等词。
- 数量冲突在卡顶显著写：“资料数量对不上：原注写2种，这里只列出1项（或3项）。无法确认是漏项还是说明不准确；以下只列文档已经写出的后续。”不能把1项写成必得，也不能把3项改成任取二。
- 99锭分支额外显示：“这段后续的按钮原文写99源石锭，但原游戏资料与这条导航没有对应起来；仍可阅读社区场景，不能确认当前可进入或领取。”
- 手动查看只改独立窗页签/阅读；主目录事件、地图绑定/当前节点、292筛选和主阅读位置完全保留。不存在自动选路或游戏动作。

同引用/同字节刷新应保留所选卡、分支、页签、文本选区和非零滚动；换事件不沿用旧引用。来源失效必须清空旧分支按钮、禁用跳转并显示未能核对，不能继续通过旧scene_key打开旧缓存。源恢复后需重新明确选择，防止按相同序号冒用另一项。

## 预计必要边界验收

1. 四入口精确身份、两版DOM和六个目标场景/按钮、原12条完整记录绑定；非target立即不适用，源缺失/错字节/暖调用后篡改回退，返回值深复制。
2. 明列分支数严格3/2/1/3、原注3/2/2/2。缺项不补、冲突不删；所有实际字段None，无概率/期望/合计奖励。
3. 20/15/1/99与每个完整未来choice一一绑定。两条15盾及两条加工品不合并；珍贵加工品具体池未知；99锭ids空及destination_mismatch保持，不能借同文原记录修入口。
4. 集中卡区别当前选择、可能后续与未来按钮；当前choice资源结果、资格checks/status、库存/本局记忆、原目录、25/57及10unparsed逐项不变。
5. 手动跳转六个精确同事件社区目标，只变独立资料窗；错事件/错分支/旧来源拒绝，不依据编号后缀或相似标题跳别处。
6. 默认不选“本次”；三个同名触碰图案、四卡切换、目标切换与源失效恢复均不跨引用。主目录选择/绑定/292作战筛选和两阅读页保持。
7. 隔离真实窗口验证集中卡和手动原文页可读、两个冲突醒目、无英文ID泄漏、刷新保留非零滚动与选区，1050×720不增主窗口最低高度。没有当前游戏随机结果样本时不宣称实际发生/领取验收。

最大风险是措辞让玩家把“后续按钮写明20希望”读成“本次一定获得20希望”，或把社区可阅读场景当实际进入目标。分层文案、默认未选、固定未知字段和不触及状态引擎是本设计的必要成本；不以消除冲突/减少待办数字换取看似完整。

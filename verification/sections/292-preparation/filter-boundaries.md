# 292：流程场景/选项筛选的独立只读边界审查

本文件仅为设计审查，不是实现或测试回执。基准 HEAD 63ec130238dfff0a65b8b648518328834f815725；没有运行 Qt、测试、游戏或聊天，没有更改 live 源码。

## 最小接口与范围

现有 `NodeCatalogPanel.event_stage` 的 UserRole+1 三元组 `[scene_key, choice_key, stage_id]` 已足够标识普通固定预览；洞中宝通用池还有第四项 `generic_next_floor`。`choice_key` 本身已带事件及场景身份，不能改用标题、原选项 ID、stage_id 或下拉序号代替。

本节可只在节点面板增加“全部场景/所选场景”和“全部选项/所选选项”两个手动阅读筛选，按当前选中的完整身份过滤既有 `event_battle_links` 结果，再使用既有 `stageSelected(str)`。默认“全部”保持旧结果域。场景和选项的选择只是资料阅读，不声明当前游戏进度。

把来源说明放在这些筛选器或现有作战选择框旁即可，不需要新后端或战斗预览 API。现有 `stageSelected(str)` 已丢失来源，不能声称它足以让 BattlePreview 长期记住来源、返回分支或区分同 ID 的不同来源；这些若要交付，应另作明确范围，不能在292暗中扩入。

## 必须防止的回归

| 情境 | 必须保持的行为 | 具体控制 |
| --- | --- | --- |
| 默认全部 | 仍列出既有全部来源候选，精确 tuple 域不缩 | 五事件共8条 battle link；008保6个别名，014/015/016各保3个精确选项-stage行；017按已知下一主层池 |
| 同名选项跨场景 | 用社区 choice_key 区分，而非标题或原ID | 016 `休想骗我` 在scene2/5/6三处均可映射同一原choice_ro6_bat5_4；`拿出诚意` scene2与scene5也必须独立，后者原game_choice_ids还是空 |
| 同stage来自不同选项 | 当前筛选来源 tuple 不得被旧stage_id覆盖 | 014普通分支与紧急分支都可能有ro6_e_t_3；015为e_t_4，016为e_t_5 |
| 相同关卡原文件的别名 | 不按地图文件或中文名称去重 | 008 ro6_t_13/c_5、t_14/c_6、t_15/c_7 六ID全部可达；同level不证明实际实例/符文语境相同 |
| 普通/紧急分支 | 复用旧过滤结果，不增加逆命题 | 无明确紧急文字的014/015/016分支仍保NORMAL+FOUR_STAR；明确升级分支仍只FOUR_STAR |
| 无作战选项 | 空作战列表、禁用按钮，不能回退为全事件作战 | 015 `果断求饶`、014 `兴趣缺缺`等选择后不得显示兄弟分支作战 |
| 场景没有直接战斗 | 不把后续场景作战当成当前选项立即结果 | 016多个前置场景及scene7社区导航说明；仅直接battle link所在场景可列其具体作战 |
| 洞中宝未知下一层 | 保留已知资料文字，空池、禁用入口 | floor=None、floor6、special_region=True不能从目录筛选/旧选择补出下一主层 |
| 洞中宝已知下一层 | 保留旧固定普通池与不完整声明 | floor2旧模型有6固定候选，floor3有7；完整服务器池/实际选择仍未知，不造概率 |
| 同事件刷新 | 场景key、选项key、stage完整tuple、阅读状态稳定 | 相同来源/上下文刷新不重置筛选、折叠、搜索、文本选择/滚动；blockSignals避免递归及自动跳到其它资料 |
| 切换事件 | 不继承前事件同名选项或stage来源 | 仅在完整事件身份一致时复用场景/选项；新事件默认全部或明确可用新选项，不能悄悄沿用旧choice |
| 上下文改变使候选消失 | 清掉失效stage，不回退旧全域或继续发旧ID | 已知floor→unknown/special；先前有池后变空时按钮必须禁用 |
| 已排除资格 | 仍可显式阅读和固定资料预览 | 原验收明确允许已列条件不符的来源参考；不把资格状态当服务器实际可选，也不把它变成禁用全部资料的开关 |
| 历史来源 | 沿用现有历史上下文隔离 | 不借当前资源/库存推定历史费用与资格，不把选中的资料场景写入node_content或RunState |
| 来源读取失败 | 不保留可触发的陈旧筛选/舞台数据 | 在现有来源失败路径中显示未知/原文；至少不能因筛选缓存让不再属于当前结果的stage按钮继续发射 |
| 技术开关与返回节点页 | 不重置手动分支与选定stage | 技术开关只换阅读字段；既有 stageSelected 仍只用于助手预览，不操作游戏 |

## 最小验收建议

1. 默认全部时按完整 tuple 对照旧结果：008、014、015、016和已知floor的017；不新增一套机制计算。
2. 016同名/同原ID跨三场景的选择隔离与同事件refresh保留；切换事件后身份重置。
3. 014普通分支双变体/紧急分支单变体，以及无作战兄弟选项空列表/禁用。
4. 008六别名仍可逐个发出原精确stage_id，不按同名/同level去重。
5. 017已知池→未知/特殊区域时旧stage失效；与已有下一主层验收复用，不宣称新池覆盖。
6. 已排除资格仍可固定参考预览，实际可选/实际stage始终未知；只读图、本局状态无写入。

本节不应再写“新增事件到作战跳转”“新增紧急过滤”“新增洞中宝下一层池”，这些能力已存在并有旧验收。新增价值是玩家能够按资料流程与具体选项缩小和保持预览范围。

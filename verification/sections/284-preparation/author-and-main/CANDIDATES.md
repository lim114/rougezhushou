# 284/285 功能候选建议（只读准备，尚未实现）

建议顺序：**284 做扩展干员技能面板的 primitive 传递；285 做同一现有校准入口的扩展干员四层/全部技能对照，并执行最终完整可用全量。** 这两组分别增加主计算能力与可实际使用的校准入口；均不新增孤立诊断 query。P2 的真实时钟、实例、热更新和实机配对缺口不能因此销成全部完成。最终目标285，不开286。

## 先纠正前提

1. 真实目录是 **32 个 operator 键、87 个技能**；首三人9技能，其余29键78技能。历史“常用30”不能当覆盖分母。额外形态也占独立键。公开目录及源码清单已实际读出，见 `candidate-source-inventory-284.json`（SHA256 `6bce17fb029aff6267a05e37e12db99e7eb75f375db2a1a365de7db83ace9549`）。
2. 283 已给所有扩展干员的常态五属性挂上同一 finalizer；缺的是技能 ATK/AS 的输入资格。不能重新把常态接入、原87技能伤害模型或283共同算式计作284新功能。
3. `Combat.plan` 一开始确实使用 `base*(1+atk_bonus+bb.atk)+atk_flat`、`base_speed_reference+bb.attack_speed`；但后续有多处 **本体 attack/speed_reference 改写**。直接对所有技能套初始 bb 会错。所有改写位置已保存在来源清单；要么在消费该 primitive 的同一点传递，要么保留该字段未知，不能从最终输出反除推回。
4. 现有“导入当前干员条件”按钮已经可缓存32人的当前情景；实际阻碍是 `calibration._scenario` 硬限首三人。不是需要另造页面或 query。
5. 参数与名义模型已知不证明实际 modifier 库存、正常 native 调用、codec 回环、技能生效或相位。新增结果沿用283的条件算式/actual unknown 分离。

## 候选 A：扩展本体技能面板的直接 primitive 传递（推荐284）

**新增用户能力**：当前主结果里，扩展干员技能攻击/攻速不再一概显示“输入未知”；对已明确消费的本体模型 primitive 显示同源的技能条件算式、FP精度/范围及未证边界。原伤害、治疗、充能/周期、conditional 总量和支持范围保持。

**可闭合范围**：

- 通用公式未被局部 attack/speed_reference 改写的分支可整组覆盖。只读初筛的16键/42技能是：桃金娘、梅、维荻、灵知、水月、伊内丝、望、真言、异格星熊、维什戴尔、梓兰、卡达、异格拉普兰德、苏苏洛、古米、术师阿米娅。确切ID/技能ID在清单；这是候选范围，不是已完成计数。每一分支仍须核对本体/召唤物、攻击倍率与面板增量的区别。
- 异格能天使S2偷取攻速、黍S3播种攻击/攻速、夜刀技能天赋额外攻击、可露希尔重置/特性倍率、深海色本体重置、陈与两异格阿米娅分阶段、遥S2条件重置、祥子S2模式与安洁天赋等，要在原实际消费处同步 primitive，或维持未知；不能扩大通用资格冒称完整78技能。后续源码审阅确认酒神三个技能和圣聆初雪三个技能没有此类本体变量改写，可加入通用部分；它们的特殊伤害与时钟不因此核验。
- 不同字段可分别闭合：攻击特殊但攻速通用时，不必把两个都抹为未知；反之亦然。技能 HP/DEF/MR 未在原模型形成的输入不凭空补。

**依据**：`rouge/operator_engine.py::Combat.plan/calculate` 的真实已选模型 primitive；`rouge/data/catalog.json` 固定 `a550f5e048bb94e7cdefc6eb97a4091f0c4c7add` 黑板/天赋参数；283 source-manifest 已绑定的普通四桶、五范围与精度证明。这里只复用有证的名义解释，不从参数猜新增 native operator 脚本。没有实际时钟或当前热更新的新证。

**改动点**：`operator_engine.py` 在构造/改写本体值时保留字段级 terms，随 `plan` 的 `full` 返回；`calculate` 使用它替代 `unknown_skill_terms()` 的一刀切；`panel_native_bridge.py` 沿用同一 `_record/finish`，不另外解析藏品/技能库。必要时只给已审计分支配置显式资格，不引入另一个算术引擎。

**必要验收**：通用支路、ATK/AS各自特殊支路、仍未闭合的反例、已选模组/潜能/普通效果/符文/限时AS组合；各阶段 `model_value` 对应原结果；实际已消费来源不二次解析；已知字段与未知字段分开；原模型快照不变；actual/完整 native 永远不因名义参数变成已证。只检查实际改动必要用例；不重跑旧33或283父38充数。

**风险/成本**：泛型自动捕获很容易把每击倍率、召唤物攻击或阶段末值当本体面板；应优先整组通用支路，再逐项吸收特殊改写。若限定只补桃金娘两个小值则组太小，不建议单独计节。

## 候选 B：扩展现有四层/技能校准到实际支持干员（推荐285）

**新增用户能力**：选中已支持扩展干员后，可直接导入当前条件，在原“面板”入口查看培养→符文→常态→技能的同源结果；原“技能”入口能列该干员所有已开放/未开放技能及各自已证分项、完整未知、名义面板精度。无需切回首三人，也不需另外查询或填写白值。

**可闭合范围**：全部32个支持键的培养与四层包装；技能按固定实际技能列表，不假设都是3个。所选干员矩阵按其自身条件计算。首三人旧默认9项、context token、compare_panel证据类型/actual unknown 和旧结果兼容保留。284没闭合的技能字段在校准里仍是未知，不变成“所有87原生核验通过”。

**依据**：现有 `operator_attributes`、87技能明确模型与 source-backed 283/284主结果；`calibration.panel_layers` 已证明只复制 main 的 native record；`app.py` 已把当前 scenario交给 `OfflineToolsPanel.set_scenario`，`_import_scenario` 已有明确用户导入动作。扩展的是调用准入与同一结果呈现，不是新增游戏机制。

**改动点**：`calibration.py` 为 panel/compare/所选干员skill矩阵单独校验支持集，不要全局放开 `OPERATORS` 让首三人特定天赋/模组worksheet误接其他人；`offline_tools_view.py` 沿用现有入口、分支和持久选择，必要时补所选干员技能清单；不增加query。保持导入是明确动作，自动刷新不覆盖编辑和结果。

**必要验收**：2技能/3技能、医疗/先锋/召唤、一个有特殊阶段仍未知的干员；培养锁技能与模组归属；切干员不继承他人专属条件；主结果与校准 exact reuse、禁止第二次求 native；原首三人9项/compare语义不退化；真实测试窗口可导入一名扩展干员并保持刷新/选项/光标/滚动。最终285全量仍须原完整可用范围；全量本身不替代本组新增能力。

**风险/成本**：若仅把错误消息去掉而无实际可用矩阵/层次呈现，收益不够。跨干员矩阵尤其不能把原干员模组、base_attack、专属事件键复制给他人；优先按“当前选中干员的所有技能”处理，旧首三人跨人默认另保留。

## 候选 C：有证多阶段技能的阶段面板（备选，不建议同时塞进A）

**新增用户能力**：陈S2、近卫阿米娅S2、医疗阿米娅S2分别并列开启/斩击前与强化后面板/条件算式，用户能看到自己正在对照哪一阶段；现有单个 `skill_attack` 是末阶段值，不能默认代表开启值。

**依据/可闭合**：`research/p2-chen-phase-reference/{NOTE.md,source-receipt.json}`、`p2-amiya-phase-reference`、`p2-amiya-input-qualification` 与当前引擎已明确的 `chen3_s2[respawn_buff].atk`、击倒叠层、`amiya_hit_targets` 上限。直接在消费处捕获前后 primitives，复用同一 finalizer。已有条件伤害/phase-reference不是新能力；只有新增阶段面板与校准映射才可计本组。

**必须保留未知**：实际斩击结束、强化起点、击倒顺序/当次伤转疗、技能结束、碰撞与完整回转。不能把6秒/35秒/32秒参数变成实际交接时刻，也不能倒改前段攻击。

**改动/验收**：engine在原分支保留具名panel快照→bridge同一结果携带阶段身份→现有校准/报告并列；声明0/上限/超限、前后ATK差、当前观察窗口与完整未知保持、每击倍率不混成面板。需原87模型对照/来源绑定，仅此组不能声明新 native 施放时钟。

**判断**：这是独立有价值的特殊分项，但实现和读者理解成本高于B。若A对特殊分支需要更多证据，可用C作为下一组集中处理，不能把简单拆行或旧phase文档重复计功。

## 当前建议不做的事项

- 不为了赶285去“消灭”真实实例/回调/热更新未知；参数不能补出这些证据。
- 不重新接回 legacy63 等战斗条件藏品，也不改识别优先级。
- 不以普通main名义快照填282的 actual cache/ordinary-call true 输入来伪造SP完整回转；主线SP原生实例仍有来源资格缺口。
- 不把最终全量、资料归档或修测试独立算一个功能节；如果第二组没完成实质新能力，应如实保留当前节数。

这份建议没有改动生产、公共状态/进度、游戏、聊天、私人配置或本局记忆；没有执行新算例当作当前游戏观测。
